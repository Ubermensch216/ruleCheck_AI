# GRC Compliance Reviewer

GRC Compliance Reviewer는 **기준 문서**와 **검토 대상 문서**를 로컬 Ollama AI 모델로 비교하여 규정 충돌 가능성, 보완 필요 사항, 확인 불가 항목과 근거를 정리하는 단일 사용자용 문서 검토 도구입니다.

문서 원본과 검토 결과는 사용자의 PC에 저장되며 외부 클라우드 LLM으로 전송하지 않습니다. 기본 AI 모델은 `gemma4:e2b`입니다.

> 이 시스템의 결과는 법률·규제·감사 전문가의 최종 판단을 대신하지 않습니다. AI가 제시한 판정과 인용 근거를 반드시 사람이 다시 확인한 뒤 사용하세요.

## 1. 시스템에서 할 수 있는 일

- 기준 문서와 대상 문서를 각각 업로드합니다.
- 기준 문서의 모든 조항을 대상으로 검토를 수행합니다.
- 관련 있는 대상 문서 조항을 검색하고 양쪽 문서를 비교합니다.
- 각 조항을 `적합`, `일부 보완 필요`, `충돌 가능성`, `확인 불가`로 분류합니다.
- 판정 이유, 권고 조치, 기준 문서 근거, 대상 문서 근거를 함께 제공합니다.
- 전체 위험도, 검토 커버리지, 쟁점 목록, 조치 로드맵, 미확인 정보를 보여줍니다.
- 검토 결과를 PDF 보고서로 내려받을 수 있습니다.
- 완료된 검토를 이력에서 다시 열거나 영구 삭제할 수 있습니다.

```text
기준 문서 업로드 → 대상 문서 업로드 → AI 모델 선택 → 검토 실행
        → 조항별 근거 검증 → 결과 확인 → PDF 보고서 다운로드
```

## 2. 지원 문서와 제한 사항

| 형식 | 확장자 | 처리 방식 |
| --- | --- | --- |
| PDF | `.pdf` | 페이지별 텍스트와 위치 정보 추출 |
| Word | `.docx` | 제목, 문단, 표 셀 추출 |
| 한글 개방형 문서 | `.hwpx` | 구역, 문단, 표 구조 추출 |
| Excel | `.xlsx` | 시트명, 셀 주소, 표시값 추출 |
| 일반 텍스트 | `.txt` | 인코딩과 줄바꿈 정규화 |
| Markdown | `.md` | 제목과 본문 구조 추출 |
| CSV | `.csv` | 행과 열의 표시값 추출 |

다음 항목은 현재 버전에서 지원하지 않습니다.

- 이미지로만 구성된 스캔 PDF의 OCR
- 레거시 한글 문서인 `.hwp`
- 암호로 보호된 PDF 또는 Office 문서
- 다중 사용자 계정, 로그인, 권한 관리
- 외부 클라우드 LLM

파일 한 개의 최대 크기는 기본 `30MB`, 추출된 텍스트의 최대 길이는 기본 `2,000,000자`입니다. Excel 수식은 실행하지 않고 파일에 저장된 표시값만 읽습니다.

## 3. 가장 빠른 실행 방법 — Windows 개발 모드

처음 실행할 때만 3.1~3.3 단계를 수행합니다. 이후에는 Ollama가 실행된 상태에서 `npm run dev`만 실행하면 됩니다.

### 3.1 필수 프로그램 설치

다음 프로그램이 필요합니다.

- [Node.js](https://nodejs.org/) `22.13` 이상
- npm `11` 이상
- [Ollama](https://ollama.com/) `0.32` 이상
- Git — 소스 코드를 Git으로 내려받는 경우에만 필요

PowerShell에서 설치 여부를 확인합니다.

```powershell
node --version
npm --version
ollama --version
```

명령을 찾을 수 없거나 버전이 낮으면 해당 프로그램을 설치 또는 업데이트한 후 PowerShell을 새로 여세요.

### 3.2 Ollama 모델 준비

Ollama를 실행한 뒤 기본 모델을 내려받습니다.

```powershell
ollama pull gemma4:e2b
ollama list
```

`ollama list` 결과에 `gemma4:e2b`가 표시되면 준비가 끝난 것입니다. Windows용 Ollama는 보통 설치 후 백그라운드에서 자동 실행됩니다. 연결 오류가 발생할 때만 별도 PowerShell에서 다음 명령을 실행하세요.

```powershell
ollama serve
```

이미 Ollama가 실행 중이면 `address already in use` 메시지가 나올 수 있습니다. 이 경우 추가로 실행할 필요가 없습니다.

### 3.3 프로젝트 설치

PowerShell에서 프로젝트 폴더로 이동한 후 의존성을 설치하고 환경설정 파일을 만듭니다.

```powershell
cd D:\Dev\ruleCheck_AI
npm install
Copy-Item .env.example .env
```

이미 `.env` 파일이 있다면 `Copy-Item`은 실행하지 않아도 됩니다. 기존 `.env`를 덮어쓰지 마세요.

### 3.4 개발 서버 실행

```powershell
npm run dev
```

브라우저에서 다음 주소를 엽니다.

- 사용자 화면: [http://127.0.0.1:5173](http://127.0.0.1:5173)
- API 상태 확인: [http://127.0.0.1:3000/api/health](http://127.0.0.1:3000/api/health)

`.env`에서 `PORT=3100`처럼 포트를 변경했다면 API 주소도 해당 포트로 바뀝니다. 사용자 화면의 주소는 개발 모드에서 계속 `5173`입니다.

서버를 종료하려면 실행 중인 PowerShell에서 `Ctrl+C`를 누릅니다.

## 4. 사용자 매뉴얼

### 4.1 시작 전 확인

화면 위쪽의 연결 상태를 확인합니다.

- `Ollama 연결됨`: AI 검토를 시작할 수 있습니다.
- `연결 확인 필요`: Ollama 프로그램이 실행 중인지 확인합니다.
- 모델 목록: 기본값은 `gemma4:e2b`입니다. 목록이 비어 있으면 `ollama pull gemma4:e2b`를 실행하세요.

문서를 올리기 전에 다음을 권장합니다.

- 문서가 암호화되어 있지 않은지 확인합니다.
- PDF에서 글자를 마우스로 선택할 수 있는지 확인합니다. 선택할 수 없다면 스캔 PDF일 가능성이 높습니다.
- 기준 문서와 대상 문서의 역할을 구분합니다.
  - 기준 문서: 준수 여부를 판단할 법령, 규정, 지침, 표준
  - 대상 문서: 기준에 맞는지 검토할 사규, 계약서, 정책, 절차서

### 4.2 문서 업로드

1. `기준 문서` 영역에서 파일을 선택합니다.
2. 업로드와 분석이 끝날 때까지 기다립니다.
3. 파일명, 페이지 수, 글자 수, 파싱 경고를 확인합니다.
4. `대상 문서` 영역에서도 같은 방법으로 파일을 선택합니다.

업로드한 문서에 경고가 표시되면 내용을 확인하세요. 경고가 있더라도 검토를 진행할 수 있는 경우가 있지만, 글자가 거의 추출되지 않았거나 페이지가 비어 있다면 원본 문서를 다시 준비하는 것이 좋습니다.

### 4.3 검토 시작

1. 사용할 AI 모델을 선택합니다. 특별한 이유가 없다면 `gemma4:e2b`를 사용합니다.
2. 필요하면 검토 제목을 입력합니다. 예: `정보보호 지침 대비 사내 정책 검토`.
3. 기준 문서와 대상 문서가 모두 준비되었는지 확인합니다.
4. `검토 시작` 버튼을 누릅니다.

검토는 백그라운드에서 진행됩니다. 화면에는 현재 단계, 처리한 조항 수, 전체 조항 수, 진행률이 표시됩니다. 기본 설정에서는 한 번에 하나의 검토만 실행합니다.

검토를 취소하면 현재 AI 호출이 중단된 뒤 상태가 `취소됨`으로 바뀝니다. 취소된 검토는 자동으로 이어서 실행되지 않으므로 필요하면 새 검토를 시작하세요.

### 4.4 결과 읽는 방법

#### 종합 위험도

| 위험도 | 의미 |
| --- | --- |
| `High` | 중대한 충돌이 있거나 높은 심각도의 충돌이 여러 건 발견됨 |
| `Medium` | 충돌, 보완 필요, 중요한 미확인 정보 또는 불충분한 커버리지가 있음 |
| `Low` | 모든 기준 조항을 검토했고 충돌·보완 필요·중요 미확인 항목이 없음 |

위험도는 AI가 임의로 정하는 값이 아니라 저장된 조항별 결과를 기준으로 서버가 계산합니다.

#### 조항별 판정

| 판정 | 의미 | 권장 대응 |
| --- | --- | --- |
| `적합` | 대상 문서가 기준 요구사항을 충족하는 근거가 확인됨 | 근거를 사람이 최종 확인 |
| `일부 보완 필요` | 일부 내용은 있으나 구체성이나 범위가 부족함 | 권고 조치를 반영해 문서 보완 |
| `충돌 가능성` | 대상 문서 내용이 기준과 상충할 가능성이 있음 | 우선순위에 따라 전문가 검토 및 개정 |
| `확인 불가` | 필요한 내용이나 유효한 근거를 찾지 못함 | 누락 문서·정보를 추가하고 재검토 |

#### 커버리지와 KPI

- 커버리지: 전체 기준 조항 중 실제 처리된 조항의 비율입니다.
- KPI: 판정별 건수와 심각도별 건수를 요약합니다.
- 커버리지가 `100%`보다 낮으면 일부 기준 조항이 정상 처리되지 않았다는 뜻이므로 결과를 확정해서는 안 됩니다.

### 4.5 쟁점과 근거 확인

쟁점 목록에서 항목을 선택하면 상세 정보가 열립니다.

- 판정과 심각도
- 판정 이유
- 권고 조치
- 기준 문서의 조항, 페이지, 인용문
- 대상 문서의 조항, 페이지, 인용문
- AI 신뢰도
- 사람 검토 필요 여부

인용문은 원문에서 실제로 찾을 수 있는지 시스템이 검증합니다. 그래도 문맥이 잘못 해석될 수 있으므로 페이지와 조항을 기준으로 원문 전체를 함께 확인하세요. `사람 검토 필요`가 표시된 항목은 반드시 전문가가 확인해야 합니다.

### 4.6 조치 로드맵과 의견서 활용

- 조치 로드맵: 심각도와 판정에 따라 우선 확인할 개선 항목을 정리합니다.
- 미확인 정보: 판단에 필요한 문서나 근거가 부족한 항목을 보여줍니다.
- 의견서: 검증된 결과만 사용해 작성한 종합 검토 의견입니다.

의견서는 화면에서 복사할 수 있습니다. 내부 결재나 감사 자료에 사용하기 전에 조직의 문서 형식에 맞게 수정하고 담당자의 확인을 받으세요.

### 4.7 PDF 보고서 다운로드

검토가 완료되면 `PDF 다운로드` 버튼으로 보고서를 저장할 수 있습니다. 보고서에는 다음 내용이 포함됩니다.

- AI 검토 고지와 문서 정보
- 종합 위험도, KPI, 커버리지
- 쟁점과 양측 문서 근거
- 조치 로드맵과 미확인 정보
- 종합 의견서
- 사용 모델, 생성일, 검토 ID

화면과 PDF는 같은 저장 결과를 사용하므로 판정 건수와 집계가 동일합니다.

### 4.8 이력 다시 보기와 삭제

이력 화면에서 완료되거나 실패한 검토를 다시 열 수 있습니다. 검토를 삭제하면 연결된 검토 결과와 더 이상 다른 검토에서 사용하지 않는 문서 원본도 함께 영구 삭제됩니다.

> 삭제는 되돌릴 수 없습니다. 필요한 PDF 보고서와 원본 문서를 별도로 보관한 후 삭제하세요.

## 5. 운영 모드로 실행

개발 도구 없이 빌드된 애플리케이션 하나만 실행하려면 다음 명령을 사용합니다.

```powershell
cd D:\Dev\ruleCheck_AI
npm install
npm run build
npm start
```

브라우저에서 `.env`의 `PORT`에 맞는 주소를 엽니다.

- `PORT=3000`: [http://127.0.0.1:3000](http://127.0.0.1:3000)
- `PORT=3100`: [http://127.0.0.1:3100](http://127.0.0.1:3100)

소스 코드가 바뀌면 `npm run build`를 다시 실행해야 합니다. 서버만 재시작할 때는 `npm start`만 실행하면 됩니다.

## 6. Docker로 실행

Docker Desktop과 호스트 PC의 Ollama가 먼저 실행되어 있어야 합니다.

```powershell
cd D:\Dev\ruleCheck_AI
ollama pull gemma4:e2b
docker compose up --build
```

브라우저에서 [http://127.0.0.1:3100](http://127.0.0.1:3100)을 엽니다.

Docker 구성은 컨테이너에서 호스트 Ollama의 `http://host.docker.internal:11434`에 연결합니다. 서버를 중지하고 컨테이너를 정리하려면 다음 명령을 사용합니다.

```powershell
docker compose down
```

`./data` 폴더는 호스트에 연결되어 있으므로 일반적인 `docker compose down` 후에도 문서와 검토 결과가 유지됩니다.

연결 문제를 확인하려면 로그를 봅니다.

```powershell
docker compose logs -f grc-reviewer
```

## 7. 환경설정

환경설정은 프로젝트 루트의 `.env` 파일에서 변경합니다. 변경 후 서버를 다시 시작해야 적용됩니다.

| 항목 | 기본값 | 설명 |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | 서버 접속 주소. 보안을 위해 기본값 유지 권장 |
| `PORT` | `3000` | API 및 운영 모드 화면 포트 |
| `OLLAMA_URL` | `http://127.0.0.1:11434` | Ollama API 주소 |
| `OLLAMA_MODEL` | `gemma4:e2b` | 기본 검토 모델 |
| `OLLAMA_TIMEOUT_MS` | `180000` | Ollama 호출 제한시간, 밀리초 |
| `DATABASE_PATH` | `./data/grc.sqlite` | SQLite 데이터베이스 경로 |
| `DATA_DIR` | `./data` | 업로드 문서 저장 폴더 |
| `MAX_UPLOAD_BYTES` | `31457280` | 파일당 최대 업로드 크기, 기본 30MB |
| `MAX_EXTRACTED_CHARS` | `2000000` | 문서당 최대 추출 문자 수 |
| `MAX_ZIP_ENTRIES` | `5000` | DOCX·HWPX·XLSX 내부 최대 항목 수 |
| `MAX_ZIP_UNCOMPRESSED_BYTES` | `104857600` | 압축 해제 후 최대 크기, 기본 100MB |
| `MAX_CONCURRENT_REVIEWS` | `1` | 동시에 실행할 검토 수 |
| `LOG_LEVEL` | `info` | 서버 로그 수준 |
| `PDF_FONT_PATH` | 비어 있음 | PDF에 사용할 한글 TrueType/OpenType 폰트 경로 |

예를 들어 포트가 이미 사용 중이면 `.env`를 다음과 같이 변경합니다.

```dotenv
PORT=3100
```

PDF 한글 글꼴을 직접 지정하려면 절대 경로를 사용합니다.

```dotenv
PDF_FONT_PATH=C:\Windows\Fonts\malgun.ttf
```

## 8. 데이터 저장과 보안

- 업로드 원본: `data/documents/{documentId}/`
- SQLite 데이터베이스: 기본 `data/grc.sqlite`
- 저장 내용: 문서 메타데이터, 추출 텍스트, 조항, finding, 근거, 검토 이력
- 보관 기간: 사용자가 검토를 삭제할 때까지
- 네트워크 바인딩: 기본 `127.0.0.1` 전용
- 인증: 로컬 단일 사용자용이므로 없음

운영 시 다음 원칙을 지키세요.

- `HOST=127.0.0.1`을 유지하고 인터넷에 직접 노출하지 않습니다.
- PC 계정과 디스크 암호화를 사용해 `data` 폴더를 보호합니다.
- `data` 폴더와 `.env` 파일을 공개 저장소에 올리지 않습니다.
- 민감한 문서는 조직의 보안 정책에 따라 별도 백업하고 삭제합니다.
- 서버 로그에는 문서 본문, 프롬프트, 근거 인용문을 기록하지 않도록 구현되어 있습니다.

## 9. 자주 발생하는 문제

### 화면에 `연결 확인 필요`가 표시됩니다

1. Windows 작업 표시줄에서 Ollama가 실행 중인지 확인합니다.
2. PowerShell에서 `ollama list`를 실행합니다.
3. 연결되지 않으면 `ollama serve`를 실행합니다.
4. `.env`의 `OLLAMA_URL`이 `http://127.0.0.1:11434`인지 확인합니다.
5. 서버를 다시 시작합니다.

### `gemma4:e2b` 모델이 목록에 없습니다

```powershell
ollama pull gemma4:e2b
ollama list
```

다운로드가 끝난 후 화면을 새로고침하세요.

### 포트가 이미 사용 중이라는 오류가 발생합니다

`.env`의 `PORT`를 사용하지 않는 포트로 변경합니다.

```dotenv
PORT=3100
```

개발 서버를 재시작한 뒤 화면은 `http://127.0.0.1:5173`, API는 `http://127.0.0.1:3100`으로 접속합니다.

### PDF 업로드 후 OCR 관련 경고가 표시됩니다

이미지로만 구성된 스캔 PDF입니다. 이 버전은 OCR을 지원하지 않습니다. 문서 프로그램에서 텍스트가 포함된 PDF로 다시 저장하거나, 신뢰할 수 있는 OCR 도구로 텍스트 PDF를 만든 뒤 업로드하세요.

### 파일 형식 또는 MIME 오류가 표시됩니다

- 지원 확장자인지 확인합니다.
- 확장자만 바꾼 파일은 사용할 수 없습니다.
- 암호화되거나 손상된 문서인지 확인합니다.
- Office 또는 한글 프로그램에서 새 파일로 다시 저장한 뒤 시도합니다.

### 업로드 용량 초과 오류가 발생합니다

기본 제한은 파일당 30MB입니다. 불필요한 이미지나 시트를 제거해 파일을 줄이는 것을 권장합니다. 제한을 변경해야 한다면 `.env`의 `MAX_UPLOAD_BYTES`를 조정한 후 서버를 재시작하세요.

### 검토가 오래 걸립니다

검토 시간은 기준 조항 수, 대상 문서 길이, PC의 CPU·GPU 성능, AI 모델 로딩 시간에 따라 달라집니다. 첫 호출은 모델을 메모리에 올리기 때문에 더 오래 걸릴 수 있습니다. 진행률이 계속 갱신되는 동안에는 정상 처리 중입니다.

### 서버 재시작 후 진행 중이던 검토가 실패로 표시됩니다

비정상 종료 당시 실행 중이던 검토는 데이터 일관성을 위해 자동으로 `failed` 처리됩니다. 문서가 남아 있다면 새 검토를 시작하세요. 완료된 검토 이력은 그대로 유지됩니다.

### PDF의 한글이 깨집니다

Windows에서는 보통 맑은 고딕을 자동으로 찾습니다. 문제가 계속되면 `.env`에 `PDF_FONT_PATH=C:\Windows\Fonts\malgun.ttf`를 지정하고 서버를 재시작하세요.

## 13. 권장 운영 절차

1. Ollama와 `gemma4:e2b` 모델 상태를 확인합니다.
2. 원본 기준 문서와 대상 문서를 별도로 보관합니다.
3. 검토를 실행하고 커버리지가 100%인지 확인합니다.
4. `Critical`·`High` 및 `사람 검토 필요` 항목부터 원문과 대조합니다.
5. 미확인 정보를 보완하고 필요하면 다시 검토합니다.
6. 담당 전문가의 최종 확인 후 PDF 보고서를 보관합니다.
7. 보관할 필요가 없는 검토는 이력에서 영구 삭제합니다.
